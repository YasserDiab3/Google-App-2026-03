# مؤشرات النمو والهجرة المحتملة

## مؤشرات يُنصح بمراقبتها

| المؤشر | لماذا |
|--------|--------|
| عدد الصفوف لكل ورقة رئيسية | Sheets يبطئ مع عشرات الآلاف من الصفوف الثقيلة |
| عدد طلبات Apps Script يوميًا | حدود الحصة اليومية للمشروع |
| زمن `readFromSheet` / `batchReadSheets` في السجلات | اكتشاف بطء القراءة أو الكاش |
| نسبة Cache HIT مقابل MISS | ضبط TTL وإبطال الكاش بعد الكتابة |

## حدود Apps Script (تذكير)

- وقت تنفيذ واحد لكل طلب (نطاق تطبيق يحدده Google).
- عدد الطلبات المتزامنة والحصص اليومية — تختلف حسب الحساب والمشروع.

## مسار هجرة مستقبلي (Firebase / Supabase)

1. عزل الوصول للبيانات في طبقة خدمة واحدة في الواجهة (لا تستدعي شكل الصف مباشرة من كل موديول عند الإمكان).
2. تثبيت عقد البيانات (DTO) بين الواجهة والخلفية.
3. ترحيل ورقة ورقة أو كيانًا كيانًا مع ازدواجية القراءة/الكتابة خلال فترة انتقالية.

المرجع البرمجي للبدء: [`Frontend/js/modules/services/data-repository.js`](Frontend/js/modules/services/data-repository.js) (واجهة رقيقة حاليًا فوق التكامل الحالي).

## اختبارات

- اختبارات الوحدة الكاملة لـ Apps Script تتطلب أدواتًا خارجية (مثل clasp + jest مع حدود)؛ يُفضَّل البدء بدوال نقية واختبارها محليًا إن نُسخت إلى JS.
